Troubleshooting

Blank content, missing windows, stale pixels, visible old frames, resize flicker, or waiting until resize ends are defects, not acceptable tradeoffs between settings. Use the status and one-change-at-a-time process below to isolate the failing route.

Passing example: the graph reports an active Custom compositor-visual route immediately.

Unavailable example: choices remain inspectable and include the failed prerequisite without replacing the active route.

A choice is unavailable

  1. Read the persistent status area; it identifies the first unsupported route requirement.
  2. Restore Target, Surface, Host, and Copy policy to Auto.
  3. Restore Buffers 3, Latency 1, Sync 1, Alpha 255, and a six-digit color key.
  4. Use automatic Display and Hardware Adapter selection.
  5. Then change one node at a time. Compatible changes activate immediately.

A window is missing from captured content

DWM Private Visual is expected to show the composed desktop, taskbar, and other windows. Missing application content is not an expected feature limitation. Reapply the route, confirm the selected host and surface in Configuration status, and compare another capture API only to isolate which capture path is failing.

  1. Confirm the missing window is visible on the same desktop and not minimized or cloaked.
  2. With DWM Private Visual selected, move the source window and verify that its magnified visual moves in the same frame and retains correct z-order.
  3. Check desktop wallpaper, taskbar, a classic HWND application, Chrome/Edge, and an Electron application such as GitHub Desktop.
  4. Change only Capture API to compare coverage, then restore the failing route before recording evidence.

When reporting the defect, include the capture API, graphics API, host, surface, adapters, presentation target, and complete Configuration status text.

Blank or transparent MAG window

  • No-redirection must be paired with DirectComposition or Presentation Manager.
  • Return Surface and Host to Auto to restore a compatible ownership pair.
  • Use Opaque alpha while diagnosing content attachment.
  • If only one backend is blank, select GDI as a baseline and inspect the status reason for the original backend.

Flicker, stale pixels, or late frames during move/resize

  • Switch Target, Surface, and Host to Auto and retest before changing the capture API.
  • Use sync interval 1 and latency 1 while diagnosing pacing.
  • If the problem occurs only with one capture API, compare another API to isolate the capture path without treating the fallback as a fix.
  • Record the selected graphics/capture/host combination and the complete Configuration status text when reporting the defect.

What to observe

  • The enlarged client area must be initialized before it becomes visible; no white frame, transparent hole, or previous desktop area should appear.
  • The magnified source, minimap, outline, and hit-test/UI rectangles must correspond to the same published client geometry.
  • Moving, activation changes, and resizing must not resurrect an older queued frame.
  • Visual updates must continue during the modal loop rather than appearing only after the mouse button is released.
  • Resource-generation diagnostics should remain stable for moves/activation and should change on resize only when capacity is actually exceeded.

Move is smooth but resize is slow

  1. Restore Auto target/surface/host/copy policy, sync 1, latency 1, and three buffers.
  2. Observe whether the slowdown begins only after crossing a particular width/height. That boundary can identify reservoir growth or swap-chain buffer replacement.
  3. Compare repeated resize within the new larger capacity. Continuous reallocation at every size is a defect.
  4. Capture the graphics/capture/host route and Configuration status together with the requested and actual client sizes.

Startup is slow or shows a white frame/busy cursor

  • MAG should not show an uninitialized application frame while expensive graphics/capture resources are still being created.
  • Restore automatic adapters and presentation choices to rule out repeated initialization of an unavailable explicit route.
  • If startup differs by backend, record time-to-first-valid-frame for GDI and the failing GPU backend without treating GDI as the permanent fix.
  • Record whether Help extraction, adapter enumeration, capture permission/runtime activation, or renderer creation precedes the delay.

An adapter disappeared

Explicit selections are stored by adapter LUID and output device name. Docking, driver changes, Remote Desktop, GPU disablement, or monitor removal can invalidate them. Reopen Settings and select Auto, the current display, or an available hardware adapter. Strict zero-copy also requires compatible capture, hardware, and display ownership.

High latency or low performance

  • Use Auto copy policy and Auto hardware adapter.
  • Avoid GDI BitBlt or traditional layered presentation when strict GPU-only performance is required.
  • Avoid WARP except as an explicit diagnostic fallback.
  • Keep maximum frame latency at 1 unless a backend requires otherwise.
  • Cross-adapter routes can require an additional transfer and are rejected by strict zero-copy unless validated.

UI rectangles or zoom origin are wrong

  • Verify Windows display scale and the monitor on which MAG is currently located.
  • At 1.0×, verify Window mode aligns with the desktop behind MAG unless the minimap source has been pinned.
  • Enable mouse-relative wheel zoom and confirm the desktop point beneath the pointer remains stationary through each zoom step.
  • Check all four client edges, minimap hit testing, and source-rectangle clipping after crossing a monitor with a different DPI.

Help does not open

MAG extracts its embedded help package to the current user's temporary directory. Verify that the temporary directory is writable and that Windows HTML Help is available. Closing MAG closes all of its Help windows and removes the extracted package.

Reset saved settings

Close MAG, then remove the per-user HKEY_CURRENT_USER\Software\mag registry key. The next launch recreates defaults: automatic presentation choices, opaque output, 3 buffers, latency 1, sync 1, and automatic adapters.
